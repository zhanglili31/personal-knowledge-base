# Personal Knowledge Base

一个面向长期使用的 AI-native 个人知识仓库。

目标很简单：**人负责输入与判断，AI 负责理解、整理、关联、检索和 Git 管理。**

## 第一次使用

如果根目录存在 `初始化.md`：

1. 用 TRAE 打开整个仓库目录。
2. 把 `初始化.md` 交给 AI。
3. 告诉 AI：

```text
按照这份文档帮我完成初始化。能自动完成的全部直接完成，只有必须我操作时再一步一步告诉我。
```

之后由 AI 检查并配置 Git、GitHub、TRAE 插件、MarkItDown 和知识库环境。

初始化完成后，AI 会把 `初始化.md` 自动归档到 `archive/system/`。

## 日常使用

普通用户不需要学习 Git 命令。

你只需要直接告诉 AI 自己想做什么，例如：

```text
帮我把这个文件整理进知识库，原文件保留。

把这条新信息更新到我以前关于 AI Agent 的知识里。

帮我找一下我以前有没有记录过 Cloudflare。

帮我整理 inbox。

刚才改错了，帮我恢复，不要丢其他内容。

把今天的修改保存好并同步到 GitHub。
```

具体的人机协作规范见：`knowledge/GitHub使用规范.md`。

## 核心原则

1. 随手记录优先于完美分类。
2. 不知道放哪里，先放 `inbox/`。
3. 原始文件保留，AI 转换结果只是阅读层，不替代原件。
4. 长期知识优先更新已有内容，避免重复堆积。
5. 项目、长期领域、知识、记录、外部资料分开管理。
6. Markdown 是长期可读标准，其他格式通过转换工具提供给 AI 阅读。
7. Git 用于版本历史与恢复，普通使用者不需要手动操作 Git。
8. AI 不得静默删除、覆盖或大规模移动用户原始内容。

## 目录

```text
personal-knowledge-base/
├── inbox/          # 临时入口：用户可以把任何东西先丢进来
├── projects/       # 有明确目标和结束条件的事项
├── areas/          # 长期持续负责的领域
├── knowledge/      # 已提炼、可长期复用的知识
├── records/        # 决策、复盘、会议、经历等事实记录
├── sources/        # PDF、DOCX、PPTX、图片等原始资料
├── archive/        # 已结束或暂不活跃的内容
└── .knowledge/     # AI 管理协议、索引和生成内容
```

## 工作流

```text
用户输入 / 丢文件
       ↓
     inbox
       ↓
AI 识别内容与文件类型
       ↓
必要时转换为 Markdown 阅读层
       ↓
去重 / 判断归属 / 提取长期价值
       ↓
projects | areas | knowledge | records | sources
       ↓
Git 版本化并同步
```

## AI 管理规则

AI 的长期行为由 `.knowledge/RULES.md` 约束。

核心关系：

```text
人：提出目标、判断结果
AI：执行文件、工具、Git、GitHub 操作
```

Git 是底层保险，不应成为普通用户的学习门槛。
